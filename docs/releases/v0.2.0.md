Version 0.2.0, Editor Experience, completes the editor chrome that ADR 0012 decided, built in
slices S1 to S13 on version 0.1.0's engine. Its tag points to the last commit of the pull request
that added these notes, as `main` holds it after that pull request was merged by rebase (issue #67).
Planewright is still in its foundation phase: the editor labels itself a pre-release and is not a
finished editor.

## What is new

- A full-bleed canvas with the controls floating over it in islands, set in the `Planewright UI`
  typeface, Inter at 400 and 500, with the chrome's design tokens (S1, S2).
- 35 glyphs drawn for Planewright for the chrome, the tools' glyphs among them in the palette, and
  tooltips that name each control and its keys (S3).
- A menu at the top left, a Keyboard shortcuts dialog that lists every command's keys, and About
  this build, which the Pre-release tag opens (S2, S4).
- An Elements drawer that shows the count of the elements and lists them, keyboard-operable, and is
  a sheet on phones (S5).
- A selection panel that shows the selection's kind or count, position, size and turn read-only,
  with Duplicate, Delete and Edit text; on phones in portrait a selection bar and a Details sheet
  (S6).
- Saving shows only when it needs attention: a "Not saved" chip with the storage notices, which
  Hide folds into it, and one sentence when a failed save succeeds again (S7).
- Phones: in portrait the tools in a dock at the bottom with More, in landscape the whole palette
  in the top row, every target at least 44 px and the controls clear of the safe areas (S8).
- While a text is edited, a chip that names Esc and Ctrl+Enter, or Cmd+Enter on Apple platforms,
  and on a phone in portrait a Done bar above the on-screen keyboard (S9).
- A violet ring at the window's edge with a "Canvas focused" chip while the canvas has keyboard
  focus, a line under the palette that says what the active tool does, and violet pressed and focus
  states (S10), with the canvas's selection outline, handles and marquee in the same violet (S11).
- Short entrances for the menu, More, the panels, the notices, the dialogs, the drawer and the
  sheets, none of them under reduced motion; the camera never animates (S12).
- Thirty visual-regression baselines of the chrome, Linux images that CI's Chromium made and
  compares on every run (S13), and the README's screenshots of the editor (issue #52).

## Fixed

- With no storage, or after a save failed or was refused as stale, the note over an empty canvas no
  longer says that the drawing is saved in this browser (issue #86).

## What did not change

In `packages/`, only the renderer's two overlay colours changed. The engine, the document schema,
the stored records and the IndexedDB database are those of version 0.1.0.

## What it does not have

- No text formatting, style controls, arrows, notes, images, clipboard, files, import or export:
  every element is drawn in one default style, and the selection panel's figures are read-only.
- No collaboration: the drawing is kept only in this browser.
- One light theme. The end-to-end tests and the visual baselines run in Chromium only.
- B1, the redraw of 5,000 elements in view, misses its 8 ms budget in some CI runs; issue #49
  follows it. The statistical budgets do not fail CI.

## Checks

- CI and CodeQL succeeded on this tag's commit at their first attempt before it was tagged, and the
  tag's message names their runs: formatting, lint, types, the guardrails, the secret scan, the
  dependency audit, the Vitest projects with coverage thresholds, the Playwright end-to-end tests
  with the visual baselines in Chromium against the production build, the production build, the
  bundle sizes and the performance report.
- B14, the JavaScript heap with 10,000 elements and a full undo history, was measured on this
  version's production build on 2026-11-13, before the release was published, by a script through
  the DevTools protocol: 17.1 MB after loading, at most 52.2 MB with the history full and 58.5 MB in
  a heap snapshot, within its 150 MB.
- Accessibility was checked by the unit and end-to-end tests, which assert roles, names, the focus
  order and its indicators, contrast, target sizes and reduced motion. No manual screen-reader pass
  was made before this release: the maintainer waived it for versions 0.1.0 and 0.2.0 alone, and it
  is made after this version's production deployment and recorded
  ([release procedure](https://github.com/mariechristsagbo/planewright/blob/v0.2.0/docs/development/releasing.md#the-screen-reader-pass-of-v010-and-v020)).
- Every slice had an independent automated review before it merged. These reviews are not human
  approval.

## Independence

Planewright is an independent project. It is not affiliated with, endorsed by or derived from
Excalidraw or REA. Excalidraw is used only as a behavioural reference, through the observable
behaviour of its public application: Planewright uses no `@excalidraw/*` package and copies no
Excalidraw source code, assets, fonts, icons or documentation text, and its glyphs and words are
its own. REA is used only as investigation methodology and tooling. Planewright is MIT-licensed.
