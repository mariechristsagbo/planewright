**A historical release.** Version 0.1.0 records Planewright's P0 milestone, Engine Core, as `main` held it when the milestone closed on 2026-11-10. Its tag points to commit `1f8188fe2177f1d91237168c79d4e7cebbae9ebd`, the last commit of P0 (pull request #48, issue #41). The tag was made later, when version 0.2.0 was published (issue #67), and holds none of version 0.2.0's editor chrome. The files inside it are as they were on 2026-11-10, so its changelog still says that no release had been published.

## What it holds

- The repository's foundation: npm workspaces with Node.js 24.22.1 and npm 11.19.1 pinned, strict TypeScript, the quality gates, the Git hooks and CI.
- The behavioural baseline of issue #1 and the canvas-engine architecture of issue #3, with ADRs 0001 to 0011, among them the clean-room reference policy of ADR 0003.
- `@planewright/engine`, an ECMAScript-only engine built in ENG-01 to ENG-15: its math layer and ports, the document model and codec, the scene store, the undo history, the camera, geometry, hit testing and selection, the transforms, input with its gesture recogniser, the Hand, Selection, rectangle, ellipse, diamond, line, freehand and text tools with tool lock, the command registry with its keymap, local persistence with autosave, and `createEditor`.
- `@planewright/render-canvas`, the Canvas 2D renderer of the engine's frames, with the bundled open-licence fonts Inter, Patrick Hand and JetBrains Mono (ADR 0011).
- The web app's P0 page: a tool bar, Undo, Redo and zoom controls, and a canvas on which rectangles, ellipses, diamonds, lines, freehand strokes and texts are drawn, then selected, moved, resized, rotated, duplicated, deleted and nudged, and texts edited again; a keyboard-operable list of the elements beside the canvas; live regions that announce each change; and the drawing saved in the browser's IndexedDB storage and restored on reload, with notices when it cannot be saved.
- The performance harness: benchmarks, browser measurements and a bundle-size guardrail, reported in CI with the machine they ran on, and a baseline of three runs on `main`.
- The collaboration service's skeleton, a health endpoint and a hello handshake, and the protocol package at protocol version 0.

## What it does not have

- No text formatting, style controls, arrows, notes, images, clipboard, files, import or export.
- No collaboration: the service exchanges no drawing.
- One light theme and no menus. The page labels itself a pre-release and is not a finished editor.
- B1, the redraw of 5,000 elements in view, misses its 8 ms budget in some CI runs, and missed it at this commit (10.1 ms); issue #49 follows it. The statistical budgets do not fail CI.

## Checks

- At this commit, CI run 42831203394 and CodeQL run 42831203630 succeeded at their first attempt: formatting, lint, types, the guardrails, the secret scan, the dependency audit, 314 Vitest test files with coverage thresholds, 64 Playwright end-to-end tests in Chromium against the production build, the production build and the bundle sizes (engine 30.3 KB, renderer 2.5 KB and the web app's initial JavaScript 108.8 KB, against 60, 15 and 200 KB).
- B14, the JavaScript heap with 10,000 elements and a full undo history, was measured on this commit's production build on 2026-11-13, before the release was published, by a script through the DevTools protocol: 17.3 MB after loading, at most 51.1 MB with the history full and 56.9 MB in a heap snapshot, within its 150 MB.
- Accessibility was checked by the unit and end-to-end tests, which assert roles, names, focus order and indicators, contrast and target sizes. No manual screen-reader pass was made before this release: the maintainer waived it for versions 0.1.0 and 0.2.0 alone, to be made after version 0.2.0's production deployment and recorded ([release procedure](https://github.com/mariechristsagbo/planewright/blob/v0.2.0/docs/development/releasing.md#the-screen-reader-pass-of-v010-and-v020)).

## Independence

Planewright is an independent project. It is not affiliated with, endorsed by or derived from Excalidraw or REA. Excalidraw is used only as a behavioural reference, through the observable behaviour of its public application: Planewright uses no `@excalidraw/*` package and copies no Excalidraw source code, assets, fonts, icons or documentation text. REA is used only as investigation methodology and tooling. Planewright is MIT-licensed.
