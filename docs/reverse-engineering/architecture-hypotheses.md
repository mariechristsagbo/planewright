# Architecture hypotheses

Everything here is **inference [I] or hypothesis [H]** about how the reference is built, drawn
from the observations in the other documents. None of it was confirmed from source code, and
none of it is a design decision for Planewright. It only bounds which behaviours an independent
implementation must reproduce.

## Implications for Planewright (non-binding)

These are design inputs to be decided in ADRs, not conclusions:

- Persisted-scene **semantics** that users can observe: bindings and groups, and z-order once it is observed (R-50). Whether
  undo history survives a reload was not observed [U]. The storage format can still be
  independent.
- Collaboration needs an end-to-end-encryption story with the key kept client-side if feature
  parity on privacy is a goal.
- File flows need both a picker-based path and a download/upload fallback.
