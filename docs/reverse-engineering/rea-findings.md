# REA findings: what REA established and what needed other tools

REA 6.8.0 at build `5b953e13…`. Sessions s1–s3 used the project-local MCP server. Sessions s5–s7
used the REA CLI of the same build (`../rea-build/scripts/rea.mjs`), because the MCP tools were
denied permission in that non-interactive session (see [checkpoint](checkpoint.md#blockers-and-residuals)).
Raw Evidence stays outside the repository. `evidence/sessions.json` lists the IDs found in
retained files; IDs that survive only in a session transcript are listed below.
`evidence/rea-windows.json` (generated by `research/excalidraw/rea-windows.mjs`) summarises every
retained REA observation window: its bounds, what the tool retains, what it retained, and which
driver steps started inside it. The window bounds, retention and driver-step facts below are
taken from that file. Three facts are not in it and come from raw records outside Git: the load
lifecycle offsets, the start time of scenario 13's Delete keypress, and the s6 storage names
(see [limitations](limitations.md#tooling-limits)).

## 1. Established directly by REA [O]

- **Target listing.** One page target on the loopback endpoint. `about:blank` is not listed
  (unsupported URL) and 5 or 6 non-page targets are excluded. This rests on the retained CLI
  records; the committed index keeps only their IDs.
- **Page inspection of the initial load** (`ev_e87d6771`). It covers only the initial empty page
  (35 named controls) in a 2 s window. Secondary surfaces and the mobile shell come from driver
  ARIA snapshots, not from REA. It established:
  - the accessibility tree (199 nodes) with toolbar names and shortcut descriptions;
  - the DOM size (385 nodes);
  - the storage key inventory with values redacted;
  - 9 scripts with module flags and sizes.
- **Storage inventory during scenario 13** (`ev_13a4756f`, s6). The localStorage keys matched s1.
  The IndexedDB names also include `workbox-expiration`, which the s1 inventory did not list.
  Cache Storage held 2 caches (the Workbox precache and one named `fonts`); s1's initial
  inspection listed 1 and its later inspection (`ev_d7cf0a58`) 3.
- **REA windows during driver input.** What each window can show depends on the tool:
  - `observe_web_session` (`ev_58bb47ed`, `ev_73a3c3b4`) **retains navigation and lifecycle
    metadata only**. By its own limitation statement it does not capture requests, WebSocket
    traffic or console messages, so these two windows say nothing about them.
    - `ev_58bb47ed` (s6, scenario 02): 12 timeline rows, all from 02's own page load: one
      `navigation_committed` row and 11 lifecycle events. The commit row has no timestamp,
      which REA states does not by itself place it inside the window; the driver's `goto`
      started 0.97 s after the window was armed. No other navigation was retained while the
      5 drags and 1 freedraw path ran.
    - `ev_73a3c3b4` (s7, scenario 10): 1 lifecycle row (`firstimagepaint`) and no navigation
      while 3 touch drags and 12 taps ran.
  - `inspect_web_page` (`ev_13a4756f`, s6, scenario 13) retains request, WebSocket and console
    metadata, but only for the allowed origin `https://excalidraw.com` and only from the moment
    REA attached. Between 16:11:07.044 and 16:11:32.276 it retained **0 requests, 0 WebSocket
    connections and 0 console events**. That span covers all 3 drags and all 20 scene reads of
    scenario 13, and the Delete keypress of its clear, which started at 16:11:07.053, 9 ms after
    coverage began (raw s6 timeline). It does not cover the Ctrl+A before it, which started at
    16:11:06.457, the first driver step inside the window. Limits:
    - requests to the page's other origins (font CDN, analytics, Sentry, Firebase) are excluded
      by policy and are not represented;
    - console events without an allowed source URL are excluded, and console text was not
      requested;
    - worker observation is unavailable (`unavailable_sections: workers`);
    - it is one 25 s window in one session [O, medium].
  - **Not established by REA:** whether drawing causes any request, WebSocket frame or console
    output in general, on another origin, or in scenarios 02 and 10. No causal statement is made
    either way. The driver netlog has timestamps that could be correlated with these windows
    without a new live session; that has not been done (see the
    [residual matrix](residual-matrix.md)).

## 3. Needed the external driver (REA lacks the primitive) [O]

- **Pointer:** canvas drags, modifier clicks, right-click, wheel and Ctrl/Shift+wheel.
- **Keyboard:** chords and key down/up, for example Space+drag.
- **Touch:** single- and multi-touch through `Input.dispatchTouchEvent`.
- **Viewport emulation:** device metrics, touch and user agent, applied once per session and then
  asserted.
- **File drop:** a self-generated PNG; native-dialog handling.
- **Reads of session-created state:**
  - scene geometry, appState fields, clipboard shape and URL fragment shape;
  - layout metrics (CSS viewport, DPR, screen, touch points, canvas backing store).

  REA's storage inventory redacts values by design.

- **Inventory of secondary surfaces:** ARIA snapshots of menus, dialogs, panels and sidebars.
- **Every behaviour entry** in the [behaviour analysis](behavior-analysis.md) rests on driver
  probes, ARIA snapshots or screenshots. REA contributed none of the scene, selection, zoom or
  storage values cited there.

## 5. REA limitations met

1. Network and console capture start at attach (`attach_limited`). Page-load request metadata
   came from the driver netlog.
2. Third-party origins are policy-filtered unless listed explicitly. Every retained window
   allowed only `https://excalidraw.com`.
3. `observe_web_session` retains navigation and lifecycle metadata only; it cannot show requests,
   WebSocket traffic or console output.
4. Large results (84–91 KB; 2 MB with script sources) exceed the client's inline limit and were
   saved to files.
5. The MCP server restarted twice during s1. Evidence held only in memory from the first
   connection was lost.
6. `analyze_web_bundle` timed out on the main chunk at the default 30 s.
7. The environment block reports the browser's own user agent, not the emulated one, and the
   platform and architecture as unknown.
8. `list_browser_targets` keeps URL fragments, so REA must not run while a collaboration room is
   open; REA records from s1 retained the room key that way.
9. Without the MCP server, records cannot be assembled into a validated bundle.
10. `capture_browser_scenario` (REA-driven locator flows) was not used.
